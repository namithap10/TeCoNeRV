# Dataset Setup

This repository uses the metadata files in `data/dataset_meta/` to resolve dataset paths. The paths in these metadata files assume the following layout:

```text
data/
  dataset_meta/
  UVG/
    beauty_1080/
      f00001.png
      ...
    bosphore_1080/
    ...
  HEVC/
    BasketballDrive_1920x1080_500/
      f00001.png
      ...
    ...
  MCL-JCV/
    videoSRC01_1920x1080_30/
      f00001.png
      ...
    ...
  kinetics_2023/
    train/<class>/<video>.mp4
  kinetics_720p/
    train/<class>/<video>.mp4
    val/<class>/<video>.mp4
  kinetics_480p/
    train/<class>/<video>.mp4
```

## Datasets for training and evaluation

Kinetics-400 is used for training and for evaluation on a small validation subset. UVG, HEVC, and MCL-JCV are the additional evaluation datasets. The directory layout above matches the released metadata files directly.

## Kinetics-400

Training metadata:

- `k400_2023_train_cls400_50_720p.js` — 400-class Kinetics-400 training subset at original 720p resolution
- `k400_2023_train_cls400_50_480p.js` — 400-class Kinetics-400 training subset, preprocessed to 640x480

Evaluation metadata:

- `sub400_k400_2023_val.csv` — one validation clip per class, read from `data/kinetics_720p/val/`

Directory layout:

- Downloaded source videos: `data/kinetics_2023/`
- 720p training subset and validation subset: `data/kinetics_720p/`
- 480p training subset: `data/kinetics_480p/`

The 720p training metadata points to videos already available at 1280x720 in the downloaded source. The 480p training metadata points to videos resized from the downloaded source, as described below.

Source: https://github.com/cvdfoundation/kinetics-dataset

### Generating the 480p split

The 480p training videos were generated by resizing each video and center-cropping to 640x480. Note for reproducibility: this preprocessing does not apply antialiasing, whereas evaluation-time transforms in the codebase use torchvision antialiasing. The released 480p videos and trained checkpoints correspond to the preprocessing described here.

To regenerate the 480p split from the downloaded source:

```bash
python scripts/resize_kinetics_480p.py \
  --metadata-file data/dataset_meta/k400_2023_train_cls400_50_480p.js \
  --source-root data/kinetics_2023/train \
  --output-root data/kinetics_480p/train \
  --workers 8
```

## Additional evaluation datasets

### UVG

The repository expects the seven standard UVG sequences as RGB PNG frame directories under `data/UVG/`:

- `beauty_1080`
- `bosphore_1080`
- `honeybee_1080`
- `jockey_1080`
- `shakendry_1080`
- `yachtride_1080`
- `readysteadygo_1080`

Sequence names and target paths are defined in `data/dataset_meta/uvg_hd.csv`. Frames must be named `f00xxx.png` starting from `f00001.png`. All sequences are 1920x1080 derived from the 2.5/5-second raw YUV source at 120 fps; `ShakeNDry` has 300 frames and the remaining six have 600 frames each.

If starting from the raw YUV files rather than pre-extracted frames, convert each sequence to PNG and place the frames in the directory structure above.

Source: https://ultravideo.fi/dataset.html

### HEVC

The HEVC common test set is organized into Classes A–E. This repository provides metadata for Classes B, C, and E, which are the classes reported in the paper. Classes A and D are excluded as they fall outside the 480p–1080p resolution range evaluated here.

- Class B: 5 sequences at 1920x1080
- Class C: 4 sequences at 832x480
- Class E: 3 sequences at 1280x720

Expected directory names are defined in:

- `data/dataset_meta/hevc_class_b.csv`
- `data/dataset_meta/hevc_class_c.csv`
- `data/dataset_meta/hevc_class_e.csv`

Raw YUV filenames follow the form `<SequenceName>_<width>x<height>_<frame_count>.yuv`, for example:

- `BasketballDrive_1920x1080_500.yuv`
- `BasketballDrill_832x480_500.yuv`
- `FourPeople_1280x720_600.yuv`

These are the standard HEVC common test sequences from the JCT-VC common test conditions, used in ITU-T H.265 evaluation. Download the YUV files, place them in a single directory, and extract frames with:

```bash
python scripts/extract_yuv_frames.py \
  --dataset hevc \
  --input-dir /path/to/hevc_yuv \
  --output-root data/HEVC
```

The extraction script verifies the number of extracted PNG files against the frame count in the filename.

### MCL-JCV

Download the 1080p source YUV videos and extract the 24 sequences listed in `data/dataset_meta/mcl_jcv_24_1080p.csv`. Only 24 of the 30 source videos are used due to intellectual-property restrictions on the remainder, as noted in the official MCL website.

Sources:

- Official dataset page: https://mcl.usc.edu/mcl-jcv-dataset/
- Hugging Face mirror: https://huggingface.co/datasets/uscmcl/MCL-JCV_Dataset

Raw YUV filenames follow the form `<SequenceName>_<width>x<height>_<frame_rate>.yuv`, for example:

- `videoSRC01_1920x1080_30.yuv`
- `videoSRC05_1920x1080_25.yuv`

After downloading and unpacking, locate the `1080P/YUV_source/` directory and extract frames with:

```bash
python scripts/extract_yuv_frames.py \
  --dataset mcl-jcv \
  --input-dir /path/to/MCL_JCV/1080P/YUV_source \
  --output-root data/MCL-JCV
```
